# 性能设计

## 背景

本项目服务的本地模型，本身 token 速度就不高。
所以网关设计的重点不是“加速模型”，而是“让网关开销尽量接近零”。

## 性能原则

1. 流式优先
2. 少拷贝
3. 少转换
4. 少日志
5. 少阻塞

## 不要做的事

- 不要把完整响应先缓存在内存里
- 不要每个 token 都打详细日志
- 不要反复 parse 同一份 JSON
- 不要把 token 统计放到慢路径里
- 不要在适配器里再套一层重试风暴

## 建议的实现方式

- `async` + streaming
- 连接复用
- 统一请求对象
- 统一响应翻译层
- token 计数缓存

## 评测方法

- 对比“直连 provider”和“经过网关”的两组结果
- 默认模型先使用 `qwen2.5-coder:7b`
- 固定模型、prompt、上下文长度和采样参数
- 记录首 token 延迟、平均 tok/s、网关额外开销和 p95 抖动
- 分别测冷启动和连接复用后的稳定态

## 验收门槛

- 在 localhost 稳态下，网关引入的首 token p95 额外开销目标不超过 10ms，或不超过总首 token 延迟的 5%，取更宽松者
- 在 localhost 稳态下，总请求额外开销目标不超过 5%，且不应引入明显的非线性退化
- provider 切换成本主要来自上游，不应被网关放大
- 流式路径不应因为路由、鉴权或观测而退化为整包缓冲

## 评估指标

- 首 token 延迟
- 平均 decode tok/s
- 网关额外开销
- 上下文变长后的退化幅度
- provider 切换成本
- p95 first token overhead
- stream cancel 传播时间
